01Connecting

Open http://172.16.2.62:8600/ from any machine on the lab network. Phone, laptop, the lab PC itself — the layout adapts.

The controller address field

The Controller card at the top names the machine that is physically wired to the pump. It exists because that machine's IP has changed before and will again.

  • Type a host and press Connect, or just hit Enter.
  • A bare address gets :8600 appended, so 172.16.2.62 and 172.16.2.62:8600 are equivalent.
  • The value is saved in your browser and survives reloads.
  • Use this page's host snaps back to whichever machine served the page.
Why this field exists at all. The page must reach a program that can open /dev/ttyS1. That program is the controller. Pointing the field elsewhere retargets the whole page — readings and controls both — at a different controller.

02Reading the panel

Connection state, top right

One badge tells you what the whole system is doing:

BadgeMeaning
Stopped Pumping station off, rotor at rest. The normal idle state.
Backing pump only Station on but the turbopump motor is disabled — the roughing-down state.
Station on Station on, motor enabled, rotor not yet turning.
Running Rotor turning.
Fault 002 The drive reports an error code. See Troubleshooting.
Pump not responding Controller is reachable, the pump is not. Usually powered off.
Controller unreachable The address in the field is wrong, or the server is not running.

Rotation speed

The large figure is actual rotor speed in Hz, with a bar showing it against this pump's nominal 1500 Hz. Below it sit status chips:

Turbopump motor DISABLED Station on Pump over-temp Accelerating Setpoint reached

The motor chip matters most. If the rotor reads 0 Hz while the station is on, that chip is the reason.

Readings

FieldParameterNotes
Commanded speedP308 What the drive is commanding, in Hz. Not the percentage setpoint in Control.
Drive currentP310 Motor current. Near zero means the rotor is genuinely not being driven.
Drive voltageP313 About 23 V at rest on this unit.
Drive powerP316Motor power in W.
Error codeP303 Shows none when clear.
Pump hoursP311 Lifetime running hours.

Live values refresh every 2.5 seconds. Polling pauses when the tab is hidden and resumes the moment you come back.

03Main controls

Every button here confirms before acting. See Safety model.

ControlDoes
Start pumping station Sets PumpgStatn. Powers the backing pump through the relay box and spins up the turbopump, unless the motor is disabled.
Stop Clears PumpgStatn. Station off, rotor coasts down.
Standby on / off Runs at the standby setpoint instead of full speed (66 % on this unit).
Acknowledge fault Clears a latched error. The only control that does not ask for confirmation, because it cannot move anything.

Speed setpoint

The number field and slider are linked; set either. Range is 20–100 %, and values outside it are rejected with a message rather than silently clamped.

Applying a setpoint also switches the drive into rotation-speed-setting mode (P26 = 1). Until that mode is active the setpoint has no effect, so the panel sets both for you.

04Accessory connectors

What is reachable over RS-485 was established by reading every parameter number from 0 to 999 on this drive unit. It implements 64. Three of the four connectors are controllable.

HEAT/TMSCasing heating

This unit is a TMS installation (temperature management system), not a plain casing heater — so it has a real temperature setpoint rather than just on/off.

  • Heating on / off — P001.
  • TMS setpoint, 30–90 °C — P704.
  • Readouts: actual temperature, max temperature, whether the regulator is engaged, and whether the output is wired for heating or sealing gas.
The pump casing gets hot and stays hot after switching off. The manual warns the high-vacuum flange must not exceed 120 °C.

VENTVenting valve

  • Enable venting / Block venting — P012.
  • Mode — P030: 0 controlled venting, 1 no venting, 2 venting on.
  • Vent speed 40–98 % — P720, the speed below which venting starts.
  • Vent time 6–3600 s — P721, how long the valve stays open.
Venting raises the pump to atmosphere. Do not vent a spinning rotor outside the controlled-venting profile.

FV PUMPBacking pump

There is no independent on/off. The backing pump is switched through the relay box by the pumping station, so it starts and stops with Start pumping station. What you can set is how it behaves once running:

  • Mode — P025: 0 continuous, 1 intermittent, 2 switch-on delayed.
  • Switch-on / switch-off thresholds in W — P711 / P710.
No feedback. The drive unit has no parameter reporting whether the backing pump is actually turning — only that the relay was commanded. Confirm by ear.

FANAir cooling

Not controllable over RS-485, by design. The cooling unit plugs into the drive unit's dedicated FAN connector and the TC 600 drives it directly. The full 0–999 sweep found no fan parameter, and the accessory configuration parameters other Pfeiffer units use for air cooling (P35–P38) are not implemented on this firmware. The panel says so rather than offering a button that does nothing.

05Procedures

Roughing down — backing pump only

The usual first step: evacuate the foreline without spinning the turbopump. Because the backing pump has no separate switch, this takes two moves in order.

  1. Disable the turbopump motor (MotorPump = 0).
  2. Start the pumping station. The relay box powers the backing pump; the rotor stays at 0 Hz.
  3. Confirm: badge reads Backing pump only, speed 0 Hz, drive current near 0 A.

From a terminal, if you prefer:

curl -X POST http://172.16.2.62:8600/api/command \
  -H 'Content-Type: application/json' \
  -d '{"action":"motor_off","confirm":true}'

curl -X POST http://172.16.2.62:8600/api/command \
  -H 'Content-Type: application/json' \
  -d '{"action":"on","confirm":true}'

Starting the turbopump

Once the foreline is down, re-enable the motor. The station is already on.

curl -X POST http://172.16.2.62:8600/api/command \
  -H 'Content-Type: application/json' \
  -d '{"action":"motor_on","confirm":true}'
Run-up monitoring is active with a 15-minute limit. If the foreline is not low enough the drive will trip rather than grind away. Starting a turbopump against atmosphere causes heating and is bad practice.

Shutting down

  1. Press Stop. The rotor coasts down — this takes minutes from full speed.
  2. If you disabled the motor for roughing, re-enable it so the rig is left in its default state. Otherwise the next person's Start pumping station will silently fail to spin the turbo.

06Safety model

Anything that physically moves the pump is guarded twice:

  1. The page asks you to confirm, naming the action.
  2. The API rejects the request unless it carries an explicit confirm flag. A stray link or a page refresh cannot start the pump.

Writes also go through an allowlist that is deliberately narrower than "everything writable". The RS-485 address, parameter-set selection and service line are not exposed — a mis-click on the address would silently orphan the pump from the controller.

There is no authentication unless the server was started with --token. Anyone who can reach port 8600 can start and stop the pump. Acceptable on an isolated lab network; not on a shared one.

07Troubleshooting

Controller unreachable

The browser cannot reach the address in the field.

  • Check the address, and that the machine is on the network.
  • Check the server is running: ssh esarodriguezm@172.16.2.62 'pgrep -af webserver.py'
  • If the lab PC's IP changed, put the new one in the field.

Pump not responding

The controller is fine; the RS-485 link is silent. In order of likelihood:

  1. The TC 600 is powered off. By far the most common cause.
  2. The HXSP-485 converter came unplugged, or moved to a different serial port.
  3. D+ and D− swapped — the pump goes completely silent. Swapping them back is harmless to try.
A quick way to tell these apart. On the lab PC run sudo cat /proc/tty/driver/serial and look at the ttyS1 line. If rx is 0 with no framing errors, nothing is driving the receive line — unpowered pump, or a wiring fault. If rx is climbing with framing errors, something is talking but garbled: wrong baud, wrong polarity, or another device on the bus.

A fault code is shown

Press Acknowledge fault to clear a latched error. If it returns immediately, the underlying condition is still present. Error-code meanings are in Pfeiffer document PM 0547 BE, which is not in this repository — this unit's history holds one entry, Err002.

Readings time out intermittently

Only one program can sensibly own the serial port. If you run tc600ctl.py on the lab PC while the web server is polling, they contend and both see timeouts. Use the web API, or stop the server first.

08Running the server

The panel is served by webserver.py on the machine wired to the pump.

# start
cd ~/tc600-control
(setsid python3 webserver.py --serial /dev/ttyS1 --address 1 --port 8600 \
    > ~/tc600-web.log 2>&1 & echo $! > ~/tc600-web.pid)

# stop
kill $(cat ~/tc600-web.pid)

# log
tail -f ~/tc600-web.log
Use the PID file rather than pkill -f webserver.py. That pattern also matches the SSH command carrying it, so it kills your own session.

Useful options:

OptionMeaning
--serialSerial port. /dev/ttyS1 here — onboard COM2.
--addressRS-485 address, 1 on this pump.
--portHTTP port, default 8600.
--tokenRequire X-Token on API calls. Strongly advised off an isolated network.
--bindInterface to listen on. Default all.

Editing web/index.html takes effect on the next page load — the server reads it from disk per request, so no restart is needed for UI changes. Changes to webserver.py or the tc600 package do need one.

The server does not survive a reboot as run above. deploy/tc600-web.service is a systemd unit for that, deliberately not installed — enabling it starts unauthenticated pump control on every boot.

09API reference

Everything the page does is available for scripting. JSON in, JSON out, with permissive CORS so a page on one host can drive a controller on another.

EndpointReturns
GET /api/pingIdentifies the service, its serial port and address. Cheap; touches no hardware.
GET /api/stateIdentity, live status, units, and mode flags. Reports connected: false within about 1.3 s if the pump is silent.
GET /api/accessoriesThe HEAT/TMS, VENT and FV PUMP parameter groups, plus the writable allowlist.
POST /api/commandExecutes an action. See below.

Actions

Writable parameters

param accepts only these names: Heating, TMSHeatSVal, CfgOut4, EnableVent, VentMode, VentSpd, VentTime, OpModeBKP, SwOnBKP, SwOffBKP, GasMode, RUTimeCtrl, EnableBrake. 

# read everything
curl -s http://172.16.2.62:8600/api/state | python3 -m json.tool

# set the TMS setpoint to 55 C
curl -X POST http://172.16.2.62:8600/api/command \
  -H 'Content-Type: application/json' \
  -d '{"action":"param","name":"TMSHeatSVal","value":55,"confirm":true}'

Responses are {"ok": true, ...} or {"ok": false, "error": "..."}. The result field carries the value the pump echoed back, which is its own confirmation of what it accepted — not just what you asked for.
